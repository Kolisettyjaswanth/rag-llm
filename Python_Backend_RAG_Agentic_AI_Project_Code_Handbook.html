CONCEPT: Python environment, virtualenv, pip, pinned requirements

1. WHAT IS IT?
A Python interpreter plus an isolated package environment. pip installs packages listed in a requirements file.
2. WHAT DOES IT DO?
It makes imports such as FastAPI, SQLAlchemy, pgvector, and sentence-transformers available to the process.
3. WHY DID I USE IT IN THIS PROJECT?
RAG and API behavior depend on compatible versions across the backend image and tests.
4. HOW DID I USE IT?
Versions are pinned in backend/requirements.txt; Docker installs them during image build.
5. WHERE IS IT USED?
backend/Dockerfile, backend/requirements.txt, ignored myenv/.
6. HOW DOES IT CONNECT TO THE REST OF THE PROJECT?
The interpreter loads the application modules and their third-party dependencies.
7. HOW DOES IT HELP COMPLETE THE RAG PROJECT?
It supplies the embedding, chunking, database, API, and testing libraries.
8. WHY DID WE USE THIS APPROACH?
Reproducible Docker builds and explicit dependency versions are easier to validate than an unmanaged global environment.
9. WHY NOT THE MAIN ALTERNATIVES?
A system-wide install risks conflicts; an unpinned requirements file risks drift.
10. WHAT WOULD BREAK IF IT WERE REMOVED?
Imports fail and the backend image cannot start or test.
11. COMMON FAILURE / ERROR
Dependency resolution, Python-version, CPU-wheel, or package API incompatibility.
12. HOW TO DEBUG OR TEST IT
Run python --version, pip show, rebuild Docker, and run pytest inside the backend container.
13. INTERVIEW ANSWER
“I separate host tooling from a pinned Python 3.11 Docker runtime so the API and RAG dependencies are reproducible.”

CONCEPT: Python collections and None

1. WHAT IS IT?
Variables bind names to objects; lists are ordered mutable collections; dictionaries map keys to values; tuples are fixed ordered values; None represents absence.
2. WHAT DOES IT DO?
The provider builds a list of chat messages and a JSON-compatible dictionary.
3. WHY DID I USE IT?
HTTP payloads and source records are naturally represented as nested Python collections.
4. HOW DID I USE IT?
messages.append(...), dictionary literals, result.get(...), and optional artifact values.
5. WHERE IS IT USED?
ollama_provider.py, rag_service.py, routes.py, schemas/tests.
6. HOW DOES IT CONNECT?
Collections carry user input, prompts, source metadata, and API serialization between layers.
7. HOW DOES IT HELP RAG?
Retrieved chunks become source dictionaries and prompt context.
8. WHY THIS APPROACH?
It matches JSON and SQL result shapes without unnecessary wrapper classes for every intermediate value.
9. WHY NOT ALTERNATIVES?
A custom object for every payload would add ceremony; raw strings would lose structure.
10. WHAT BREAKS?
Malformed keys or missing values can produce invalid prompts, responses, or provider payloads.
11. COMMON FAILURE / ERROR
KeyError, wrong value types, mutable-list reuse, or None passed to code expecting text.
12. DEBUG / TEST
Print safe shape information, assert keys in tests, and inspect response models.
13. INTERVIEW ANSWER
“The project uses dictionaries and lists at integration boundaries because providers and HTTP responses are JSON-shaped.”

CONCEPT: objects, inheritance, abstract interfaces, dataclasses

1. WHAT IS IT?
A class defines object behavior; inheritance reuses/interface-matches behavior; an ABC declares required methods; a dataclass stores structured values.
2. WHAT DOES IT DO?
LLMProvider standardizes generate; Ollama and Claude implement it; AgentRoute stores route data.
3. WHY DID I USE IT?
Skills can depend on one LLM interface while the concrete provider changes.
4. HOW DID I USE IT?
Constructors assign configuration; methods use self; providers inherit from LLMProvider.
5. WHERE IS IT USED?
backend/app/llm, agent/router.py, services and skills.
6. HOW DOES IT CONNECT?
The agent injects an LLM object into RAG/Ship30/Artifact skills.
7. HOW DOES IT HELP RAG?
RAG generation is decoupled from the specific model transport.
8. WHY THIS APPROACH?
Polymorphism allows Ollama by default and Claude/Hugging Face as alternatives.
9. WHY NOT ALTERNATIVES?
Hard-coding HTTP calls in every skill would duplicate provider logic.
10. WHAT BREAKS?
A provider that fails to implement generate cannot satisfy the interface.
11. COMMON FAILURE / ERROR
Wrong provider selection, missing environment variables, or incompatible response shapes.
12. DEBUG / TEST
Inject FakeLLM; test one interface call and provider-specific configuration.
13. INTERVIEW ANSWER
“The abstract provider is a narrow polymorphic contract; skills depend on generation, not on Ollama’s transport details.”

CONCEPT: error handling and resource management

1. WHAT IS IT?
Exceptions represent failures; try/except handles them; with manages setup/cleanup.
2. WHAT DOES IT DO?
The chat route rolls back partial DB work and returns a safe 503; health closes its DB connection.
3. WHY DID I USE IT?
LLM/network/database failures are expected operational conditions.
4. HOW DID I USE IT?
Catch SQLAlchemy and general agent failures, log stack traces server-side, rollback, raise HTTPException.
5. WHERE IS IT USED?
routes.py, main.py, database.py, provider code.
6. HOW DOES IT CONNECT?
It protects transaction boundaries around agent execution.
7. HOW DOES IT HELP RAG?
A failed Ollama call cannot leave a user-only message committed.
8. WHY THIS APPROACH?
Users get a stable API error while operators retain diagnostics.
9. WHY NOT ALTERNATIVES?
Ignoring exceptions risks corrupted state; exposing raw traces leaks internals.
10. WHAT BREAKS?
Without rollback, later queries may see a failed transaction or partial turn.
11. COMMON FAILURE / ERROR
Ollama HTTP 500, PostgreSQL connection failure, malformed provider response.
12. DEBUG / TEST
test_chat_failure_returns_service_unavailable_and_rolls_back_user_message monkeypatches the agent.
13. INTERVIEW ANSWER
“The API treats generation as part of a DB transaction and converts operational failures into a safe 503.”

def get_db() -> Generator:

SQLAlchemy creates the engine, session factory, declarative base, ORM classes, relationships, and transaction methods. Psycopg is the driver selected by postgresql+psycopg. pgvector’s Vector(dim=384) maps embedding lists to a PostgreSQL vector column. The retriever uses SQLAlchemy text() because the pgvector distance operator is expressed directly in SQL.

Python list[float] → SQLAlchemy bind parameter → CAST(... AS vector) → PostgreSQL pgvector cosine distance → similarity float → source dict → prompt

3. WHY?

5. WHERE?
database.py, models.py, repository.py, routes, retriever.
6. CONNECTION?
DB rows are the bridge between ingestion and RAG answer generation.
7. RAG?
Embeddings and source metadata survive process restarts.
8. WHY?

9. ALTERNATIVES?

route = self.router.route(message)
if route.skill == "rag":
    result = skill.execute(db=db, question=message)

    result = skill.execute(db=db, topic=message)

The project’s agent is intentionally deterministic. The router checks artifact terms first, Ship30 terms second, and defaults to RAG. The skill performs LLM work; routing itself does not ask a model to decide. In Claude mode the application agent creates ClaudeAgentExecutor, which invokes the SDK. K. LLM Provider Python Code

class LLMProvider(ABC):
    @abstractmethod
    def generate(self, prompt: str,
                 system_prompt: str | None = None) -> str:
        raise NotImplementedError

provider = os.getenv("LLM_PROVIDER", "ollama").lower()
if provider == "ollama":
    return OllamaProvider()
if provider in {"claude", "claude-agent-sdk"}:
    return ClaudeAgentProvider()

OllamaProvider.generate builds JSON and calls /api/chat with urllib.request.urlopen. ClaudeAgentExecutor lazily imports the SDK, creates ClaudeAgentOptions, asynchronously iterates query(), and joins assistant text blocks. HuggingFaceProvider uses InferenceClient when explicitly selected and requires HF_TOKEN.

“I combine real persistence tests with cheap fakes around embeddings/providers so the important contracts are covered without making the suite depend on Ollama.”
